## 🏗️ Project Architecture Overview

We have initialized a **Modular Machine Learning Project Skeleton**. This is a professional-grade structure that allows for scalability, testing, and easy deployment.

### 📁 Folder Breakdown & Meaning

| Component | Meaning / Purpose | Reason for Inclusion |
| :--- | :--- | :--- |
| `src/` | **Source Code Directory**. This is where all the actual ML logic (data ingestion, transformation, model training) lives. | Keeps the core logic isolated from configuration and documentation files. |
| `src/__init__.py` | **Python Package Marker**. It tells Python that the `src` folder should be treated as a package. | Allows us to import modules from `src` (e.g., `from src.logger import logging`). |
| `setup.py` | **Installation Toolkit**. It contains metadata about the project (version, author) and its dependencies. | Enables us to install our project as a local package, making imports easier across the whole system. |
| `requirements.txt` | **Dependency List**. Lists all the external libraries (pandas, numpy, etc.) needed to run the project. | Ensures that anyone who clones the project can install the exact same environment using `pip install -r requirements.txt`. |
| `mlproject.egg-info/` | **Metadata generated by setup.py**. | Created automatically when we install the package in editable mode. |
| `venv/` | **Virtual Environment**. | Keeps the project's dependencies separate from the global Python installation to avoid version conflicts. |

## 🛠️ Technical Deep Dive (Interview Preparedness)

### 1. Why use `setup.py`?
**Meaning:** `setup.py` is the build script for setuptools.
**Reason:** In industry-level ML projects, you don't just run individual scripts. You build the project as a **package**. This allows you to use your own code as a library within the project, which is essential for modularity and testing.

### 2. What is `-e .` in `requirements.txt`?
**Meaning:** The `-e` flag stands for **editable mode**. The `.` refers to the current directory.
**Reason:** When we run `pip install -r requirements.txt`, the `-e .` line triggers `setup.py` to install the local `src` folder as a package. This way, if we change the code in `src`, the changes are immediately reflected in our environment without needing to reinstall.

### 3. The Power of `find_packages()`
**Meaning:** A function in `setup.py` that automatically looks for folders containing an `__init__.py` file.
**Reason:** It saves us from manually listing every sub-package in our project. As we add more folders like `data_ingestion`, `model_trainer`, etc., `find_packages()` will automatically include them.
